# 铁军知识图谱 · 搭建手册(分发版)

> 这支军队的第三件武器:把全域经验自动沉淀成**带出处的实体-关系网**。
> **定位:索引与关系网,不是第二事实源。** 图谱回答"有什么、谁管什么、和什么相关、该去哪查";一切易变状态以权威源文件为准。

## 一、为什么要建

军队跑起来之后,知识会散落在宪章、作战日志、台账、复盘记录里。没有图谱,每个新会话/新班次都要重读几十个文档才能恢复全局观,踩过的坑会再踩一遍。有了图谱:

1. **快速恢复全局观**——按层取一两个图谱文件,即可携带正确上下文开工;
2. **推理有抓手**——推理路由表把"什么场景→读什么→查什么→过什么门"显式化;
3. **不重蹈覆辙**——坑点教训库把每个坑结构化为"现象→根因→修法",派单前先检索。

## 二、三条黄金纪律

1. **权威源 > 图谱 > 记忆 > 印象。** 凡报状态先对权威源(宪章/作战日志/代码仓),凡做裁决先过门禁;图谱发现自己与权威源冲突,修图谱。
2. **结构性变化当天入谱,易变状态永不入谱。** 成员、产品、机会卡、条令、门禁的**结构**变了,当天更新图谱;而"进行到第几轮""今天跑没跑"这类易变状态一律不进图谱——图谱不是状态板。
3. **每条知识带出处。** 每张实体卡、每条关系都标注源文档路径;说不出出处的知识不入谱。

## 三、十层结构(建议按此分层建文件)

| 层 | 文件名建议 | 装什么 | 何时读 |
|----|-----------|--------|--------|
| 0 | 00-本体与实体索引.md | 实体类型体系、全实体 ID 注册表、关系类型表 | 定位实体/看全景 |
| 1 | 01-使命与战略层.md | 使命、三目标、战略教义及换算关系 | 任何裁决前(使命对表) |
| 2 | 02-组织与人员层.md | 全员档案卡、指挥链、权限矩阵 | 派单/找人/分权时 |
| 3 | 03-条令与流程层.md | 军规、评审铁律、决策框架、工作链与门禁 | 动手前(过门禁) |
| 4 | 04-产品与战役层.md | 产品档案、战役分解、内容资产、工具库 | 建设类任务前 |
| 5 | 05-战场与机会层.md | 行业带、机会卡全景、排序与触发器 | 立项/侦察/排序前 |
| 6 | 06-外部网络与同盟层.md | 外部网络、合作方、竞合关系 | 对外协作前 |
| 7 | 07-基础设施与环境层.md | 部署链、环境约束、自动化节奏、验证脚本 | 环境类操作前 |
| 8 | 08-坑点与教训库.md | 坑点卡(按域编号,三段式) | 派单前检索、故障排查时 |
| 9 | 09-时间线-大事记.md | 全事件因果链(历史层,只追加) | 需要历史脉络时 |
| 10 | 10-推理路由手册.md | 场景→知识路径路由表、权威源对照表、推理陷阱清单 | **任何任务开工前扫一眼** |

实体类型(7 类)、关系类型(10 种)、卡格式的完整定义见 [00-本体与分层模板.md](00-本体与分层模板.md)。

## 四、从零搭建(七步)

1. **落种子**:组装时 `references/knowledge-graph/` 的两件(本 README 与《00-本体与分层模板》)已复制到 `<项目>/docs/knowledge-graph/`(若没有先复制过去)——《00-本体与分层模板》就是你 00 层(本体与实体索引)的底稿;再按下表新建 01-10 各层文件;
2. **定本体**:抄模板的实体 7 类与关系 10 种,按你的业务增删;
3. **灌结构层**:先把使命层(01)、组织层(02)、条令层(03)填了——这三层来自宪章,基本照抄;
4. **灌教训层**:翻你的作战日志/项目记忆,把每个"现象→根因→修法"整理成坑点卡入 08 库——**这层价值最大,优先做**;
5. **写路由手册**:按你的实际场景写 10-手册的"权威源对照表+场景路由表+推理陷阱清单";
6. **机械校验**:`node scripts/verify-graph.mjs <项目根>`(检查文件结构、引用一致性、表行数对拍);
7. **评测验收入**:找一个"接班场景"实测——只给图谱文件不给全量文档,看新会话能否正确回答"现在有什么、谁管什么、去哪查"。答不出=图谱缺层;答错=图谱与权威源漂移。

## 五、持续运转

- **更新时机**:结构性变化当天入谱(纪律二);作战日志里出现新教训当天入坑点库。
- **更新流程**:新实体先在 00 注册表占 ID → 写对应层文件 → 跑 verify-graph;
- **评测迭代**:图谱不是建完就完——定期找独立会话(没见过源文档的)对图谱做评测打分,低分项修复后复评。作者用这套方法把图谱从 7.2 分迭代到 9.3 分(A 级;作者实测数据,供参考),每轮的教训本身也入谱。
- **机读化(可选)**:图谱稳定后可导入图数据库(Neo4j 等)做关系查询,或写成 OWL/RDF 本体做推理验证——但 markdown 图谱是唯一事实源,机器库只是它的投影;两者漂移时以 markdown 为准并重建投影。

## 六、与其他部件的关系

- 宪章(references/ 上层目录)定义"组织应该怎样"——图谱记录"组织实际知道什么";
- 作战日志(PROJECT_MEMORY)是活水——图谱是它的结构化沉淀;
- 远征军条令的"每班一件团队增强"——图谱的持续完善就是最典型的团队增强。
